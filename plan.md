## 2. Runtime modes

1. **Desktop (default):** Tauri spawns `codeci-backend` sidecar on `127.0.0.1:<random port>` (saved in settings) → full musicdl catalog + CC Rust clients. Desktop library lives in `codeci-core` SQLite (single source of truth); sidecar is stateless-ish (download dir configurable).
2. **Desktop advanced / LAN / Termux:** settings can point at external `http://host:8787` backend; app talks to it instead of spawning sidecar.
3. **Android:** no sidecar. Rust CC clients only (Jamendo/FMA/ccMixter/Audius/Wikimedia). "Full catalog" toggle reveals only when backend URL is set.

## 3. Feature scope (v1)

- Search across sources with unified result list (source badge, duration, bitrate, cover)
- **Popular-first search UX** (user requirement): default sources order = mainstream (Netease/QQ/Kuwo sidecar) for desktop; search results sorted by `raw_data.search.pop`/score where available; on Android, Jamendo exposes "charts/popular" endpoint used for the Home/ForYou rail; UI shows artist popularity where the source provides it. No random/niche results injected by the app itself
- Stream & play: HTML `<audio>` via `/stream` proxy (desktop: backend proxy or local file; android: resolved direct URL; fallback download-then-play)
- Download to disk (chosen folder, resume, progress, cancel) + offline library
- Playlist import from URL (desktop sidecar mode: `musicdl.parseplaylist`; CC sources: native playlist endpoints where available)
- **Recommendations ("Spotify-style", local)** — phase 1 `codeci-core::recs`, phase 3 Home rails:
  - Taste profile: exponential time-decay (half-life 30 d) weighted vectors over artists, genres/tags, source popularity, built from plays/skips/completions/likes
  - Co-play matrix: track×track co-occurrence across sessions → "Because you played X"
  - Candidate gen: same-artist, same-genre cosine neighbors, source popularity lists (Jamendo trending, Netease `pop`) as exploration pool
  - Ranking: `0.45·genre_cos_sim + 0.25·artist_affinity + 0.20·popularity_prior + 0.10·novelty_bonus − skip_penalty`; ε-greedy (ε≈0.2) explore/exploit
  - Queue-aware **radio mode**: station from current track (artist/genre match, dedup, popularity boost)
  - Fully local (SQLite), single-user — no collaborative filtering across users, no audio DSP in v1 (documented); "reset taste profile" in settings
  - Home rails: `For You` (top-k by score), `Because You Played` (co-play), `Top Artists → radio`, `Trending` (source charts)
- Library: favorites, history, play counts, search/filter/sort
- Playlists: create/rename/delete, add/remove/reorder tracks, cover collage
- Queue: now playing view, up-next, reorder, shuffle/repeat
- Lyrics: fetched where source provides (NetEase/QQ via sidecar); embedded via mutagen when local; WhisperLRC NOT in v1
- Settings page: theme (Liquid Glass / PixelOS Material) + accent + glass intensity, enabled sources, download dir, per-source (search_size, threadings, cookies for VIP sources, requests_overrides), proxy, backend URL (mobile), cache size, clear cache
- Onboarding: pick sources + download location + CC sources vs full catalog explanation
- Tray icon + media keys on Windows; systemd autostart optional on CachyOS
- Android: same UI, responsive layout, downloads stored in app-private/Music dir, optional external backend mode documented

## 6. Risks & mitigations

1. musicdl breaks/changes API monthly → pin version; isolate behind backend; CI smoke test hits live search weekly (scheduled workflow, non-blocking).
2. Liquid Glass perf on low-end Android → glass layer is CSS `backdrop-filter` with intensity setting + automatic fallback to Material theme if `prefers-reduced-motion`/low FPS detected; test on mid-range device.
3. Tauri sidecar bundling quirks on Windows (paths, AV false positives) → document; sign later; keep backend importable via `codes-install-backend` script as fallback.
4. CachyOS packaging drift → ship PKGBUILD + systemd unit; app works with user-installed backend too.
5. Public repo + musicdl pinning → add SECURITY note; dependabot for Rust/npm only, not musicdl pinned range.
5. Mobile CC catalog is indie-heavy (probe: "kanye west" on Jamendo → type beats only, no Kanye releases). Accept & disclose in-app ("Android build ships open/CC catalog; desktop sidecar unlocks mainstream sources"). Popular-artist CC content comes from Jamendo trending + Wikimedia Commons (classical) + ccMixter remixes of famous songs
6. Android : audio in webview requires media permissions — handled in tauri android config
7. Windows Application Control / Smart App Control can block `pycryptodome*` native DLLs → document workaround (SAC off or `CODECI_CRYPTODOME_SHIM=auto` fallback aliasing `Cryptodome→Crypto`) in docs/installation
8. musicdl signed URLs expire (~30 min) — stream proxy caches resolved URL per track id + re-resolves on failure.
